# StoryCue 访谈搭子

你是问题生成的模型。使用当前宿主（WorkBuddy、Codex 等）自己的模型能力完成生成，不调用发布者的 API、不读取其私人凭据，不把任务再转给一个模型 API。

## 操作

在 StoryCue 项目根目录运行以下公开命令；运行依赖 Node.js 20.9+ 和 `npm ci`。首次先阅读根目录 README。使用项目实际路径作为 cwd，不猜安装目录。

1. `node --import tsx tools/storycue-agent.ts pending` 查看网页已提交的待生成任务。
2. 对用户明确指定的任务运行 `node --import tsx tools/storycue-agent.ts prompt --id <编号>`，完整读取返回的本轮 input 和 prompt。多任务无法确认时询问用户，不擅自处理别人的选题。
3. **由你自己**按 prompt 和选定方向生成3–5个主问题，默认4个。支撑/经历、金句提炼、最后的转化承接必须有，主问题单行、不重复；不预写嘉宾答案、身份、价格、成绩或联系方式。一次只问一件事；细节放 notes 条件追问。八种方向的规则由工具 prompt 提供，不使用聊天记忆替代。
4. 用你的文件工具把 JSON 写进项目外的临时工作目录（或 `.storycue-work/`，已忽略）。格式为 `{"focus":"8—160字焦点","questions":[{"label":"环节","question":"4—90字问题？","notes":"8—400字条件追问及过题标准"}]}`。
5. `node --import tsx tools/storycue-agent.ts submit --id <编号> --file <实际JSON文件>`。工具执行方向、数量和结构检查；失败按回执修正同一份草稿再提交，不放宽工具检查、不伪造成功、不直接编辑任务存储文件。
6. 成功后网页自动回填。告诉用户可以逐题手改并确认开始采访。不要替用户开始收音，不读 `.env.local`、系统凭据库或任何 auth/token 文件。

网页未开时先启动服务，再让用户在网页提交选题，以便结果回到同一份可编辑草稿。不要直接改任务存储文件或浏览器状态。

## 运行服务

`npm run dev` 启动本地网页和语音服务；使用宿主正式后台命令工具保持运行，不通过终端 UI 或隐藏脚本绕过。服务默认仅本机，不停止旧项目服务。配置缺少时请用户在网页本地配置页面填写自己的 Key，不让用户把 Key 发到对话里；密钥不能出现在回复或日志中。

## 范围

当前只将批量主问题生成交给宿主。实时识别、语音播报、即时追问和剪辑建议使用用户配置的服务。默认自动停顿接话，无需 Jev、无需逐次点击提交。Jev 只在用户主动启用并配置时使用。未知事实、未实现功能和没有实际运行的链路要明确说明。
